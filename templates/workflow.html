HOW A REQUEST FLOWS

From CSV upload to answer.

Each step shows where it runs. Only the steps marked OpenAI call the AI, and it sees file IDs and result summaries, never your CSV rows. The saved LightGBM model makes every classification, and Python writes every number in a reply.

1Upload a CSV

No OpenAI call happens during an upload.

  1. Browser

    Choose a file

    Drop or choose a CSV, or click a sample button such as One row.

  2. Browser

    Send it to the server

    POST /api/upload (samples use POST /api/samples/<name>), with this session's CSRF token.

  3. Server

    Check the file

    A .csv name and type, at most {{ '%g' | format(limits.upload_mb) }} MB, and at most {{ limits.files }} files and {{ '%g' | format(limits.session_mb) }} MB per session.

  4. Server

    Check the contents

    UTF-8 text in valid CSV syntax; exact, unique column names that include every model feature and nothing unknown; 1 to {{ '{:,}'.format(limits.rows) }} rows. A row with bad values is kept and reported when a tool runs, never dropped.

  5. Server

    Store it in your session

    Saved under a random file ID that only this session can use, for up to {{ limits.session_minutes }} minutes of inactivity. The content is treated as data and never executed.

  6. Browser

    Prepare a question

    A file card appears and the chat box gets an editable question: predict row 0, classify all rows, or evaluate a labeled file. Nothing is sent until you press Send.

2Send a request

A typical request makes two OpenAI calls, shown in purple.

  1. Browser

    You press Send

    The message goes to POST /api/chat/stream, which streams progress back as each step happens.

  2. Server

    Check the request

    CSRF token, 1 to {{ '{:,}'.format(limits.message) }} characters, at most {{ limits.chat_per_minute }} chat requests a minute per session. The session is locked for this turn, and a failed turn is rolled back.

  3. Server

    Checks before any AI call

    Pasted CSV text is refused. A conditional request must name one minimum accuracy, the files and the row; if not, the server asks you, without calling the AI. A question about stored results gets no tools.

  4. OpenAI

    OpenAI call: choose

    {{ model_name }} receives the fixed instructions, the file IDs and names, summaries of earlier results, recent messages and your message. It returns one tool call, or picks a stored result to show. Strict JSON schemas, a {{ '%g' | format(limits.timeout) }}-second timeout, and stateless calls (store=false).

  5. Server

    Check the tool call

    The tool must exist, the file must belong to your session, and the row index must be a whole number from 0. In a conditional request the file and row must be the ones you named, and a prediction the accuracy rule forbids is blocked.

  6. ML model

    Run the model

    predict_single, predict_batch or evaluate runs the frozen LightGBM pipeline. The full result is stored under a result ID; a batch also writes a downloadable CSV that keeps every row.

  7. OpenAI

    OpenAI call: answer or decide

    The AI reads only the tool's summary: counts and metrics, no rows. It picks the result to show or, in a conditional request, decides from the returned accuracy whether to call predict_single. At most {{ limits.tool_calls }} tool calls per request.

  8. Server

    Write the reply

    Python writes the reply. Every number comes from the stored result, never from the AI's own words.

  9. Browser

    Show the answer

    Progress and tool events appear live; then the reply, the Tools line under it, and the activity record.
